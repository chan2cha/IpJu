# 우리집 입주노트

부부가 함께 사용할 입주 준비 앱의 **Milestone 1 로컬 시제품**입니다. 한국어 모바일 UI와 가상 데이터로 화면·입력 흐름·자금 계산을 확인합니다.

## 실행 방법

Supabase DB와 GitHub → Vercel 배포 구성을 사용할 예정입니다. 연결 절차와 현재 구현 범위는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요. `vercel.json`은 배포 전 lint/typecheck/test/build를 수행하도록 설정되어 있습니다. 현재는 아직 DB에 연결되지 않은 시제품입니다.

Node.js 22.18 이상과 npm이 필요합니다. 환경변수는 필요하지 않습니다(`.env.example` 참고).

```sh
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:3000 을 엽니다. PowerShell에서 `npm.ps1` 실행이 차단되면 모든 명령의 `npm`을 `npm.cmd`로 바꾸세요. 실행 정책을 변경할 필요는 없습니다.

### VS Code + Git Bash

이 폴더를 VS Code에서 열면 `.vscode/settings.json`에 따라 새 터미널의 기본값이 Git Bash입니다. 기존 PowerShell 터미널은 휴지통 버튼으로 종료하고 **터미널 → 새 터미널**을 선택하세요. Git Bash에서는 위의 `npm install`, `npm run dev` 명령을 그대로 사용합니다.

설정은 이 PC의 `C:\Program Files\Git\bin\bash.exe`와 fnm의 `%APPDATA%\fnm\aliases\default`를 사용합니다. 로그인 셸이 이전 PATH를 재사용하지 않도록 `ORIGINAL_PATH`를 제거하고 Node 기본 경로를 연결했습니다. 다른 PC에서 Git/Node 설치 위치가 다르면 해당 설정을 조정하세요. Git Bash에서 Node 26.13.0, npm 11.20.0 및 보조 검사 10개 통과를 확인했습니다. 검증 환경에서는 기존 `.bashrc`의 fnm 초기화에 권한 경고가 있었지만, 기본 Node 경로를 통해 npm은 정상 실행되었습니다.

```sh
npm run lint
npm run typecheck
npm run test
npx playwright install chromium
npm run test:e2e
npm run build
```

E2E는 개발 서버를 자동 실행하며, 360×800 / 390×844에서 네 탭을 검사합니다. 화면 캡처는 `test-results/`에 저장합니다. 로컬 프로덕션 미리보기는 빌드 후 `npm run start`로 실행합니다. 위 명령은 배포를 수행하지 않습니다.

## 구현 범위

- `/dashboard`: 입주 D-Day, 자금 요약, 7일 내 할 일, 최근 변경, 빠른 추가.
- `/tasks`: 카테고리·담당·완료 필터, 할 일 추가/수정 시트, 완료 체크, 삭제 확인.
- `/expenses`: 계획액/결제액/남은 결제액, 결제일 정렬, 카테고리 필터, 예시 분할 결제 내역, 추가/수정/삭제.
- `/funding`: 예상 총자금과 확정·수령 자금, 예상/확정 기준 부족·여유액, 자금원 추가/수정/삭제.
- `/settings`: 입주일 변경, 예시 구성원, 시제품 안내.
- 하단 네 탭, 최소 44px 터치 영역, 숫자 키패드, 입력 오류·빈 상태·로딩·오류 화면, 키보드 조작 가능한 모달.
- Next.js App Router, TypeScript strict, Tailwind CSS 4. shadcn/ui의 수동 설치 방식으로 Button/Dialog를 프로젝트에 두고 스타일을 조정했습니다(Radix, CVA 사용).

## 가정과 범위 제한

### 상품·업체 비교 (2026-11-06 추가)

지출 화면에서 각 항목의 **후보 추가**를 누르면 상품·서비스명, 업체명, 모델명·서비스 구성, 총 견적금액, 사이트 주소, 비교 메모를 입력할 수 있습니다. 새 지출은 먼저 지출 항목을 저장한 뒤 후보를 추가하세요.

- 비교표를 좌우로 밀어 후보별 가격과 조건을 확인합니다. 항목 이름은 왼쪽에 고정됩니다.
- 낮은 견적순 정렬, 최저 견적 표시, 최저가와의 차이를 제공합니다. 빈 금액은 미정이며 0원과 구분합니다.
- 배송·설치·추가 비용을 포함한 총액을 직접 입력하세요. 사이트 가격을 자동 수집하지 않습니다.
- **이 후보 선택**으로 이용할 후보를 표시할 수 있습니다. 선택·수정·삭제는 지출 계획액이나 결제액을 자동 변경하지 않습니다. 실제 계획에 반영하려면 **지출 수정**에서 예상/확정금액을 변경하세요.
- **사이트 열기**는 새 탭을 엽니다. HTTP/HTTPS 주소만 허용하며 스크립트 주소와 계정 정보가 포함된 주소는 거절합니다.
- 후보는 해당 지출에 연결되며, 선택한 후보를 삭제하면 선택도 해제됩니다. 지출을 수정해도 후보는 유지됩니다.
- 기존 시제품과 동일하게 새로고침하면 초기화됩니다. 환경변수·추가 의존성·DB 연결은 필요하지 않습니다.

가상 데이터는 React Context 메모리에만 있습니다. 탭 이동 시 유지되지만 **새로고침하면 초기화**됩니다. 서버·브라우저 저장소에 저장하지 않고 실제 공동 편집도 하지 않습니다. 화면에서 가능한 편집은 사용성 확인용입니다.

예시 입주일은 2026-12-20이고 D-Day와 7일 내 할 일은 현재 서울 날짜 기준입니다. 실행 날짜에 따라 임박한 할 일이 없을 수 있습니다. 기획서 계산 예시를 사용하므로 잔금 등의 금액은 실제 시세와 관련이 없습니다. 금액 미정 지출은 합계에서 제외하고 건수를 표시합니다.

DB, 로그인, 초대, RLS, Realtime, 실제 CRUD/서버 검증, 결제 기록 편집, 템플릿 선택은 구현하지 않았습니다. PWA manifest·서비스 워커·설치·오프라인·배포도 이후 milestone 범위입니다.

## 자금 계산

`lib/finance.ts`가 모든 화면의 공통 순수 계산을 담당합니다.

- 계획액 = `confirmedAmount ?? estimatedAmount`. 확정 0원은 그대로 0원입니다.
- 남은 결제 예정액 = 각 항목의 `max(계획액 - 누적 결제액, 0)` 합계. 미정 항목은 제외합니다.
- 예상 자금 차이 = 예상 총자금 - 총 계획 지출. 이미 결제한 금액을 다시 차감하지 않습니다.
- 확정 기준 차이 = 확정·수령 자금 - 총 계획 지출. 실제 계좌잔액이 아닙니다.
- 음수·소수·안전 정수 범위 초과 입력과 합계 오버플로를 거절합니다. 초과 결제는 별도 경고합니다.

기본 예시: 계획 지출 3,500,000원 / 자금 3,000,000원 / 결제 500,000원 → **부족액 500,000원**, 남은 결제 예정액 3,000,000원. 미정 지출 1건은 별도 표시합니다.

## 최신 검증 결과 (2026-11-06)

의존성이 설치된 현재 환경에서 `npm run lint`(경고 없음), `npm run typecheck`, `npm run test`를 실행했습니다. 단위 테스트는 **51개 통과**했습니다. 설치된 Edge로 360×800 / 390×844의 **전체 E2E 12개가 통과**했으며, 비교표 스크롤 보완 후 **비교 E2E 4개를 다시 실행하여 통과**했습니다. 모바일 비교표 캡처도 검토했습니다.

Playwright 기본 Chromium이 설치되지 않은 경우, Edge가 설치된 Windows의 Git Bash에서 다음 명령을 사용할 수 있습니다.

```sh
PLAYWRIGHT_CHANNEL=msedge npm run test:e2e -- --workers=2
```

검증한 항목: 후보 작성/수정/삭제/선택, 선택 후보 삭제 시 해제, 지출 수정 후 후보 유지, 사이트 링크 속성, 위험한 주소와 잘못된 금액 거절, 미정·0원, 정렬, 지출 합계 불변, 모바일 가로 넘침 방지. 개발 표시 버튼이 홈 탭을 가리는 문제도 `next.config.ts`에서 수정했습니다. 이번 변경에서는 프로덕션 빌드를 실행하지 않았습니다.

| `npm run test` | 실행 시도, `vitest` 명령을 찾지 못함 |

현재 실행 환경의 네트워크 제한으로 npm 레지스트리 접속이 `EACCES`로 실패했습니다. 로컬 npm 캐시에도 의존성이 없어 설치를 완료하지 못했습니다. **단위 테스트 전체·타입·lint·브라우저 검증 통과를 의미하지 않습니다.** 네트워크가 허용된 환경에서 위 설치·검증 명령을 실행해야 Milestone 1 완료 기준을 최종 확인할 수 있습니다.

`package.json`의 버전 범위를 지정했지만 실제 설치 조합 검증과 `package-lock.json` 생성은 남아 있습니다. 첫 설치 성공 후 생성된 lockfile을 보관하고 이후에는 `npm ci`를 사용하세요. 보조 검사는 `npm run test:smoke`로 재실행할 수 있습니다.

## 보안·성능과 다음 단계

외부 API·금융 계좌·DB 연결 및 비밀키를 사용하지 않습니다. 개인 데이터 로그, 주기적 polling, 공개 offline cache가 없으며 검색엔진 인덱싱을 막는 메타데이터를 설정했습니다. 인증이 없는 시제품이므로 실제 개인·금융 정보를 입력하지 마세요.

현재 lint/typecheck/Vitest/E2E와 모바일 비교표 검토를 완료했고, 프로덕션 빌드 검증은 남아 있습니다. 별도 요청 시 Milestone 2에서 DB·인증·가구 공유와 RLS/서버 인가, 제3자 접근 차단 테스트를 진행합니다.

기술 구성 참고: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [shadcn/ui 수동 설치](https://ui.shadcn.com/docs/installation/manual).
